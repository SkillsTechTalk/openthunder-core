# Definition of Done conformance cases

Reference behavior for any implementation of the Definition of Done evaluator (docs/BOUNDARY.md, Layer 1). Each file in
`cases/` is one case: a policy, the change, the evidence, an evaluation time, and the expected decision. An
implementation conforms when it produces the expected `state` and the expected status for every listed item.

## Case format

```json
{
  "name": "plain words: what this case protects",
  "policy": "<policy text (.openthunder/done.yml); {{key:NAME}} is replaced with the PEM public key of test key NAME>",
  "policyEditedByChange": false,
  "subject": { "repository": "example.com/acme/app", "revision": "aaaa...", "changedFiles": ["src/a.ts"] },
  "now": "2026-11-20T12:00:00Z",
  "receipts": [
    { "kind": "tests", "check": "junit", "revision": "aaaa...", "outcome": "passed", "metrics": { "executed": 3 },
      "identity": "github-actions:acme/app", "sign": "ci", "tamper": false }
  ],
  "expect": { "state": "not-done", "items": { "tests": "passed", "policy-intact": "passed" } }
}
```

Receipt shorthand: the runner expands each entry into a full `done-evidence-v1` receipt (defaults: repository from
`subject`, version `1`, empty findings and limitations). `sign` names a test key to sign with; `tamper: true`
changes the receipt after signing. Keys are generated by the runner, so no private key is stored here.

Policy approvals (optional): `"approvals": [{ "sign": "jordan", "approver": "Jordan" }]` approves the case's policy
edit (`policyEditedByChange: true`). The runner binds it to sha256 of the base policy text and of the edited text
(`changedPolicy`, or the base text plus a comment). `edit: "earlier"` approves a different edit, `base: "other"` was made
against a different base policy, `tamper: true` changes it after signing. `expect.evidenceIncludes` checks item evidence.

Statuses: `passed`, `failed`, `not-checked`, `outdated`, `not-applicable`, `exception`.
States: `done`, `done-with-exceptions`, `not-done`.
